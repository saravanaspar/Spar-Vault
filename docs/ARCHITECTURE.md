# Architecture — 0.2

`packages/vault_core` is pure Dart and has no network or storage access. It owns bounded schema-1/schema-2 parsing, CSPRNG root/password generation, unchanged legacy inner AEAD framing, Argon2id password wrappers, RFC 6238 TOTP, bounded Google migration QR parsing, ephemeral nearby pairing/AEAD and legacy ticket/package authentication.

`lib/app/vault_controller.dart` owns the live root and session epoch, serializes writes with compare-and-swap, authenticates staged restores before replacement, tracks encrypted password history/deletion records, previews and merges incoming same-root snapshots, updates encrypted preferences and rotates roots. Password KDF workers use Flutter compute on native targets. They cannot reopen an expired session.

`lib/main.dart` manages session activity/deadlines, resume expiry, privacy covers, explicit clipboard/export actions, section navigation, pagination and foreground autofill approval. `lib/ui` contains entry editors/details, restore credentials, merge choices, TOTP timers and shared input/card widgets. Soft-keyboard changes explicitly report user activity.

`lib/platform` conditionally selects native versus browser storage, integration, bridge and transfer code. Native files keep existing application-support identifiers. Browser IndexedDB keeps the previous vault record, with separate encrypted-only automatic-copy storage. `web/spar_integrations.js` provides granted File System Access or IndexedDB copy rotation; no remote assets or account API are involved.

Android Kotlin implements separate strong-biometric and system-screen-credential hardware-bound wrapping, SAF directory permission/backup rotation, native autofill certificate/cache checks and explicit secure confirmation. Website autofill fails closed because the Android form API omits the port. No external identity service or broad package-query permission is used.

Linux/Windows opt-in autofill opens a random loopback broker and private expiring state file only while unlocked. `browser/host.py` is the bounded native-messaging relay, installed for one OS user and extension ID. `browser/extension` checks target origins, requests vault approval and fills one top-frame form. Web mode connects to an exact configured open vault tab through nonce-bound messaging; it shares the vault origin's existing trust boundary.

Native nearby transfer uses NSD on Android and UDP discovery across native apps. A receiver advertises while its dialog is open; a sender chooses items and a discovered device. Ephemeral X25519/HKDF pairing produces a number shown on both devices for comparison. Only after both approve do AEAD-protected entries travel. The controller atomically imports them under the receiver’s own key without changing local preferences; exact duplicates are skipped and changed-ID conflicts are copied. Cancel/lock stops advertising, discovery and transport. The old ticket transport remains internal, with no old file/code controls in the UI. Browsers use encrypted backup export/restore.

Existing platform bundle IDs, storage paths and legacy cryptographic contexts remain unchanged. Flutter shares functionality across platforms; signing, OS permissions, packaging and hardware protections still need each target's toolchain and device validation. Complete zeroization, OS-compromise resistance, rollback prevention and security certification are not claimed.

Android setup status is exposed through the existing `spar/integrations` method channel. Authentication settings and autofill selection are awaited and rechecked, including service selection on resume. A prompt-in-progress session guard distinguishes our system authentication Activity from normal backgrounding; it never suppresses inactivity/manual/detached locking or accepts an old result. Dialog routes complete their exit transition before callers dispose text controllers, and nearby/QR/app-picker dialogs own their asynchronous lifecycle. QR decoding runs on an Android worker; cameras request permission only when scanning.

Desktop System lock has a separate native method channel. Windows CNG wraps a vault-bound root with a hardware Windows Hello key; macOS retrieves a user-presence-protected Data Protection Keychain item. Linux libfido2 verifies a fresh ES256 PIN/touch assertion and returns the transient hmac-secret to the Dart AES-GCM wrapper. Only encrypted/public binding metadata is stored outside the vault. Pending operations carry cancellation epochs; enrollment verifies the protected operation before committing. Linux and Windows register their handlers in the desktop runners; macOS registers in MainFlutterWindow.

The GitHub workflow validates both locked Dart packages and Python tests, then builds full native bundles on matching runners. Its aggregate ci check gates main releases. Version parsing rejects shell content; a tested main SHA is tagged without force-updating existing tags. Draft releases publish only after every asset is uploaded.
